# Edge-case review: theme and style system

Every branching path and boundary I could find, with what the spines say about it. "Unspecified" means neither spine nor the decision log settles it. Citations use `file › section`. Where a spine defers a question on purpose (Open Questions), the row says so, and its severity reflects the risk of leaving it deferred.

## Findings

| # | Area | Scenario | What the spines say | Severity | Suggested resolution |
|---|---|---|---|---|---|
| 1 | Settings combinations | The OS switches light/dark while the Appearance page has pending changes (applied Mode is Auto, or the pending Mode is Auto). | EXPERIENCE › Interaction Primitives (Live OS tracking) says the *app* follows the OS live. Nothing says whether the *preview*, the Pending/Applied comparison or the mode explanation ("Right now that's Light") also re-resolve, or whether the pending set survives. | medium | Auto resolves live everywhere: main app, preview (both segments) and the mode copy. | 2 | Settings combinations | Contrast on Follow system, and the OS `prefers-contrast` flips while changes are pending, or the pending value is Follow system. | Live tracking is specified (EXPERIENCE › Component Patterns › Increase contrast control; › Interaction Primitives). | 3 | Settings combinations | Windows Contrast Themes (forced colours, `forced-colors: active`). This is not `prefers-contrast: more`, and Chromium overrides every token. | Unspecified. | 4 | Settings combinations | On Linux the OS gives no contrast or dark signal (many desktop environments, some Wayland sessions). | 10 | Settings combinations | Fixed-px components don't scale with text size: top bar 72px, search pill 40px, icon button 36px, badge height 22px. | 12 | Settings combinations | The user switches the Preferences tab (Appearance to General) with changes pending. | 13 | Settings combinations | Esc on Appearance with nothing pending and no menu open. | Unspecified. EXPERIENCE › Interaction Primitives (Esc) covers menus, then discard. | low | Pass Esc through to the Preferences window's own behaviour. |
| 14 | Settings combinations | The user changes a control while the Pending/Applied switch is on "Applied". | Unspecified. EXPERIENCE › Component Patterns: the switch "changes nothing". | low | Any control change flips the switch back to Pending. |
| 15 | Settings combinations | Every setting changes at once, so the apply-bar summary is long, and at 150% text it overflows. | Unspecified. | 20 | Theme files | An empty (0-byte) file. ## Unspecified items that block a build

These need a decision before architecture or the first epic can proceed, because each one shapes a data model, a persistence key, a security boundary or a token contract.

1. **Theme identity key** (#24, #25, #26): filename, `$metadata.name` or an id. It drives config persistence, clash detection, duplicate display and reserved built-in names.
2. **Last-valid-version cache** (#27, #28): where it lives, when it's written, and what a deleted active theme does. Both fallback rules depend on it.
3. **Token value grammar and limits** (#22, #23): what counts as an "invalid value". Covers CSS-injection rules, size and alias caps, and alias cycles. This is the security boundary for files from strangers.
4. **Contrast pair table** (#29, #30, #85, #90, #97): which role pairs must pass 4.5:1 or 3:1, and what happens when an authored high-contrast variant fails. Derivation, the axe sweep and the author guide all need it.
5. **Inverse surface roles for toasts** (#96): the current mapping renders white on white in Nylas dark. It is a token-contract change.
6. **Categorical override storage and rename behaviour** (#83, #84): index or hex, and name hash or stable id.
7. **Collapse sequence past "rail, then folders"** (#8, #73): CSS px against zoom, what replaces each collapsed region, its keyboard reveal, and the final state.
8. **Window-control placement per OS in RTL, and Linux button layouts** (#72): Electron `titleBarOverlay` may not support the stated inline-end rule.
9. **Legacy migration rules** (#43–#47): config keys preserved for downgrade, community LESS fallback, multiple `core.themes`, the `styles.less` fate and LESS-variable compatibility for plugins.
10. **Windows forced colours** (#3): honour or opt out. This decides how every style renders state.
11. **Outgoing mail and print colours** (#66, #67): adapted colours must never reach a sent message, and print needs a defined palette.
12. **Toast stacking and de-duplication** (#93, #94): needed before theme-load and live-reload errors can ship.
